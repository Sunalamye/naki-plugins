# naki-plugin-ex-local-unlock

只在這台裝置上，改自家的外觀顯示。伺服器與其他玩家看到的仍是帳號實際擁有的外觀。授權 CC0-1.0。

> 本插件只改你這台裝置上看到的畫面，其他玩家看到的仍是你帳號實際擁有的外觀。改寫遊戲封包可能違反雀魂的服務條款，有被封號的風險。**只在測試帳號使用，不要在主帳號啟用。** 停用本插件後，請重新載入遊戲頁面，畫面才會完全恢復。安裝插件等於信任插件作者：插件與遊戲在同一個環境執行，Naki 無法阻止插件做其他事。

## v1（1.0.0）

需要 Naki 2.20.0 以上（receive 側變長改寫與送出守衛）。較舊的 Naki 上插件不做任何改寫，Naki log 會記一行說明。設計見 repo 的 `docs/local-unlock-v1.md`。

| 顯示 | 來源回應 | 方式 |
|---|---|---|
| 大廳主角色與它的皮膚；角色或皮膚不在清單就補進去 | `fetchCharacterInfo` | 變長改寫 |
| 自家個人資料的頭像與稱號，含沒有任何稱號的帳號 | `fetchAccountInfo` | 變長改寫，只改 `account_id` 等於自家的那一筆 |
| 對局內自家稱號與裝扮 | `authGame` | 只等長，且只在大廳已改寫之後 |

### 只改本機顯示；保證範圍

- 插件不送出任何請求，也不改任何送出封包。
- 插件宣告 Naki 的送出守衛，涵蓋 19 個換裝、稱號、角色類請求。大廳改寫一次後，Naki 把本插件標為已污染，這 19 個請求到頁面重載前都不會原樣送出，遊戲收到本機合成的錯誤回應。
- 停用插件或插件被自動移除後，守衛由 Naki 的污染接手，仍然擋下；L3 總開關開著時，插件在場會自己拒絕放行，熱停用再啟用也一樣。
- 對局內的等長改寫只在大廳已改寫、Naki 已接手守衛之後才做。只設了對局內稱號或裝扮、大廳沒有改寫時，對局內不改。
- 換句話說，生效後你在這個頁面裡**無法真的換裝**，連擁有的外觀也一樣（v1 接受的代價）。要換裝請先停用插件並重新載入頁面。
- **未守衛的入口**：19 個之外，仍有請求可能帶外觀 id 或自由文字，例如大廳聊天 `sayChatMessage`、好友訊息 `sendClientMessage`、表情統計 `logReport`、活動 `majClubActivity*`、對局內表情 `broadcastInGame`。Naki 擴充守衛名單前，這些入口不在保證內；啟用期間請不要使用大廳聊天、好友訊息與活動頁，對局內不要點表情。完整清單見 repo 的 `docs/local-unlock-v1.md` §9。

### 限制

- **對局內零稱號仍不生效**：Naki 禁止對局連線（`.lq.FastTest.*`）的變長改寫，對局內只能等長，沒有稱號的帳號照舊顯示「暫無稱號」。
- **大廳只有個人資料頁會變**（v1 範圍）：推測大廳左上角的頭像與稱號來自登入回應（未 live 確認）。登入回應禁止變長改寫，本插件不改。
- 補進清單的角色只有角色與皮膚 id，等級等其他欄位是 0。遊戲是否正常顯示、角色詳情與面板能否開啟，要 live 確認。
- 不改他人外觀、對局內角色與皮膚、大廳裝扮、稱號清單、加載 CG、語音。
- 插件不驗證皮膚是否屬於該角色，填錯的組合畫面怎麼顯示未知。
- 變長改寫一旦被 Naki 拒絕（例如頁面已因交付故障鎖死），本頁面不再改大廳，熱停用再啟用也一樣，重新載入頁面才恢復。
- 回應帶錯誤、結構不符、單值欄位重複，或角色清單裡任何一筆損壞時，整則不改。

## 行為細節

- 自家身分取自登入回應；登入回應帶錯誤、登出、被擠下線都會清掉。熱啟用或登入前就載入時身分未知，不會改寫，需重新載入頁面並重新登入。
- 對局內：每個 `authGame` 回應只與同一條連線、同一個 msgId 的請求配對；自家身分必須與該請求的 `account_id` 相同。只改自家那一筆的稱號（field 3）與裝扮（field 10 的 `item_id`），新值與原值 varint 位元組數不同時該項不改。
- 未勾選「我確認只在測試帳號使用」或未啟用時，不做任何事。
- 插件不內建任何 id。稱號、角色、皮膚、裝扮都由你在設定頁輸入；角色與皮膚要同時填才生效，皮膚 id 也用作頭像。

## 使用

1. 在插件頁啟用，開啟設定頁，勾選確認、啟用，輸入 id。
2. 重新載入遊戲頁面並重新登入。

## 未驗證

- live 尚未做（等 Naki 2.20.0 發布後由主線另派），而且只觀察、不點擊：大廳畫面是否實際顯示、補進去的角色是否正常、聊天與表情面板是否列出未擁有的表情、換裝被拒時遊戲的表現、重載頁面後是否殘留改寫資料。
- 欄位號取自 Naki repo 的 `docs/protocol/liqi.json`（2026-10-17 重抽）；`ResCharacterInfo` 與 `Account` 的欄位未用 live 封包核對。
